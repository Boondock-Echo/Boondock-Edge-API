CLI Documentation - Serial Port Commands and Messages

Overview​

The Boondock Edge Firmware communicates via a serial interface that supports:

  • CLI Commands - Host → Device configuration and control (plain text format)
  • Periodic Status Messages - Device → Host status updates (JSON format)
  • Configuration Messages - Device → Host configuration announcements (JSON format)
  • Health Messages - Device → Host system health metrics (JSON format)

CLI commands are sent as plain text (one command per line), while all device-to-host messages use JSON format for structured data exchange. Serial output is protected by mutexes to prevent message interleaving.

Serial Port Configuration​

  • Baud Rate: 115200 bps
  • Format: JSON text, one message per line
  • Encoding: UTF-8
  • Line Ending: LF (newline character)
  • Mutex: Serial output protected by g_serialMutex (1000ms timeout)

Message Format​

JSON Structure​

All messages are compact JSON with abbreviated 2-3 character field names to reduce serial bandwidth:

{
  "ty": "message_type",
  "tm": "timestamp",
  "mc": "device_id",
  "si": "session_id",
  ...fields...
}

Standard Fields​

FieldCodeTypeDescription
TypetystringMessage type: "config", "short", "health", "event"
TimestamptmstringTime formatted as "HH:MM:SS AM/PM"
Device IDmcstringMAC address or device identifier
Session IDsistringSession identifier (changes per boot)

Field Details:

Storage Information:

  • st: Storage mode active - either "SD" (SD card) or "PSRAM" (fallback memory)
  • sd: Whether device is currently using SD card for new recordings
  • Switches to PSRAM on SD card failures; returns to SD when recovered

Session Statistics:

  • rc, uc: Counters for this boot session only, reset on reboot
  • pq: Current number of files queued for upload
  • td: Total milliseconds of audio recorded this session
  • rt, ut: Time of most recent recording and upload operations

Memory Status:

  • ht: Total heap memory allocated (device RAM)
  • hf: Available heap memory remaining
  • Units auto-format: B (bytes), K (kilobytes), M (megabytes)
  • Example: "320.00K" = 320 kilobytes

Recording Metrics:

  • rs: Size in bytes of the most recent recording file
  • rd: Duration in seconds of the most recent recording
  • Useful for understanding recording patterns

Yearly Archive Statistics:

  • yr: Current year for statistics
  • yf: Total count of audio files stored on SD card
  • ys: Total storage consumed by all recordings (formatted)
  • yh: Total hours of audio recorded (all time)
  • ym: Count of calendar months containing recordings
  • yd: Count of calendar days containing recordings

System Clock:

  • tv: Time valid flag - false if RTC not synced, true if accurate
  • When false, timestamps may be unreliable

Sent for significant system events:

CLI Commands (Host → Device)​

Command Format​

Commands are sent as plain text (not JSON) via serial port, one command per line:

COMMAND [PARAMETER] [VALUE]

Commands are case-insensitive and support multiple aliases. Responses are formatted as:

COMMAND OK

or

COMMAND FAILED: [error message]

Available Commands​

Configuration Commands​

GET / SHOW / READ - Read Setting Parameter​

Usage:

GET <parameter>
SHOW <parameter>
READ <parameter>

Examples:

GET wifi.ssid
SHOW audio.samplerate
READ upload.apihost

Response:

  • Returns the current value of the parameter
  • Empty values return "(empty)"
  • Command followed by "OK" or "FAILED"

All Supported Parameters:

WiFi Settings:

  • wifi.ssid - WiFi network name
  • wifi.password - WiFi password (returns obfuscated)
  • wifi.connecttimeoutms - WiFi connection timeout (ms)
  • wifi.savedstaticip - Saved static IP address

Audio Settings:

  • audio.samplerate - Sample rate (Hz, typically 8000)
  • audio.buffersamples - Buffer size in samples
  • audio.audiothreshold - Audio threshold (0 to 100)
  • audio.prerecordms - Pre-record buffer duration (ms)
  • audio.minrecordingms - Minimum recording duration (ms)
  • audio.maxrecordingms - Maximum recording duration (ms)
  • audio.silencethresholdms - Silence detection timeout (ms)
  • audio.discardsmallfilesenabled - Enable discarding small files
  • audio.discardsmallfilesminms - Minimum file size to keep (ms)
  • audio.codecgain - Audio codec gain (dB, -3 to +24)

Upload Settings:

  • upload.apihost - Upload API server hostname
  • upload.apiport - Upload API server port

RTC Settings:

  • rtc.enabled - RTC module enabled
  • rtc.sdapin - RTC I2C SDA pin number
  • rtc.sclpin - RTC I2C SCL pin number

SD Card Settings:

  • sdcard.usesdcard - SD card enabled for storage
  • sdcard.recordtosdcard - Recording saves to SD card
  • sdcard.mode1bit - Use 1-bit SPI mode (false = 4-bit)
  • sdcard.frequency - SD card SPI frequency (Hz)
  • sdcard.formatifmountfailed - Auto-format on mount failure

Timezone Settings:

  • timezone.offsethours - UTC offset hours (-12 to +14)
  • timezone.maintenancehour - Maintenance window hour (0-23)
  • timezone.maintenanceminute - Maintenance window minute (0-59)

Global Settings:

  • wifienabled - WiFi enabled (master switch)
  • uploadenabled - Uploads enabled (master switch)
  • streamenabled - UDP audio streaming enabled
  • streamport - UDP port for audio streaming
  • streamhost / stream.host - UDP streaming hostname/IP address
  • wifitxpower - WiFi TX power level (1-10)
  • settingslocked / settings.lock / sl - Settings lock state (prevents saving changes to NVS)

Log Settings:

  • log.serialfatal - Serial fatal log enabled
  • log.serialerror - Serial error log enabled
  • log.serialwarning - Serial warning log enabled
  • log.serialinfo - Serial info log enabled
  • log.serialdebug - Serial debug log enabled
  • log.serialevent - Serial event log enabled
  • log.filefatal - File fatal log enabled
  • log.fileerror - File error log enabled
  • log.filewarning - File warning log enabled
  • log.fileinfo - File info log enabled
  • log.filedebug - File debug log enabled
  • log.fileevent - File event log enabled

Usage:

SET <parameter> <value>
CHANGE <parameter> <value>
UPDATE <parameter> <value>

SET wifi.ssid MyNetwork
SET audio.minrecordingms 1000
SET wifienabled true

  • sl → settings.lock (settings lock state)

AUTOCONFIG - Quick Configuration Setup​

Usage:

AUTOCONFIG <SSID>,<PASSWORD>
AUTOCONFIG <SSID>,<PASSWORD>,<HOST_IP>,<HOST_PORT>,<TIMEZONE_OFFSET>,<AUDIO_THRESHOLD>,<MIN_RECORDING_MS>,<MAX_RECORDING_MS>,<PRE_RECORDING_MS>

Short Version (WiFi Only):

AUTOCONFIG MyNetwork,MyPassword

Full Version (All Settings):

AUTOCONFIG MyNetwork,MyPassword,192.168.1.100,8080,-8,-45.5,1000,30000,500

Parameters (Full Version):

  1. SSID - WiFi network name
  2. PASSWORD - WiFi password
  3. HOST_IP - Upload API server IP address
  4. HOST_PORT - Upload API server port
  5. TIMEZONE_OFFSET - UTC offset hours (-12 to +14)
  6. AUDIO_THRESHOLD - Audio threshold (0 to 100)
  7. MIN_RECORDING_MS - Minimum recording duration (ms)
  8. MAX_RECORDING_MS - Maximum recording duration (ms)
  9. PRE_RECORDING_MS - Pre-recording buffer duration (ms)

Response:

  • Short version: Sets WiFi credentials, saves to NVS, prompts for "DONE" to reboot
  • Full version: Sets all parameters, saves to NVS, reboots after 2 seconds (or "DONE" to reboot early)
  • Shows summary of all configured parameters
  • Password is masked in output for security

Usage:

SAVE
STORE

Response:

  • Returns "SAVE OK" or "SAVE FAILED"
  • Note: If settings are locked, save is blocked and warning message is shown

Usage:

LOAD
REFRESH

Response:

  • Reloads all settings from NVS storage

LOCK - Lock/Unlock Settings​

Usage:

LOCK <0|1|true|false>

Parameters:

  • 1, true - Lock settings (prevents saving changes to NVS)
  • 0, false - Unlock settings (saves all pending changes to NVS)

Response:

  • When locking: Shows warning that all changes will be temporary
  • When unlocking: Saves all pending changes accumulated while locked
  • Lock state is persisted to NVS

Behavior:

  • When Locked:

    • All settings changes are applied in RAM only (temporary)
    • Changes are lost on reboot
    • Auto-save is blocked (shows warning message)
    • Explicit SAVE command is blocked (shows warning message)
    • Lock state itself can always be saved

  • When Unlocked:

    • All settings changes are saved to NVS automatically (with debounce)
    • Changes persist across reboots
    • Normal auto-save behavior resumes

Examples:

LOCK 1                    # Lock settings
SET streamport 6001       # Change port (temporary, not saved)
LOCK 0                    # Unlock and save all pending changes

Aliases:

  • SET settingslocked <value> - Same as LOCK command
  • SET settings.lock <value> - Same as LOCK command
  • SET sl <value> - Short alias for LOCK command
  • GET lock / GET settingslocked / GET settings.lock / GET sl - Get current lock state

Command Processing​

Settings Processing​

Commands are processed by settings_processSerial() which:

  1. Reads incoming serial data
  2. Parses JSON command
  3. Executes command via settings_setParam(), settings_getParam(), or settings_updateAllFromJson()
  4. Sends response via serial with mutex protection

Settings Lock and Auto-Save​

Auto-Save Debounce:

  • Settings changes are automatically saved to NVS after 1 second of inactivity
  • Prevents excessive NVS writes during rapid configuration changes
  • Background task monitors for pending saves

Settings Lock:

  • When locked, all settings changes are temporary (RAM only)
  • Changes are lost on reboot unless unlocked
  • Lock state is persisted to NVS
  • Unlocking automatically saves all pending changes
  • Useful for testing configurations without committing to flash

Response Format​

Responses follow the standard message format with appropriate fields:

Success Response:

{
  "ty": "response",
  "status": "ok",
  "cmd": "SET",
  "param": "audio.samplerate",
  "value": "8000"
}

Error Response:

{
  "ty": "error",
  "status": "failed",
  "cmd": "SET",
  "error": "Invalid value: must be between 0 and 100"
}

Thread Safety​

Serial Mutex​

The serial port is protected by a mutex (g_serialMutex) to prevent message interleaving:

  • Timeout: 1000ms (for CLI output)
  • Periodic Messages: Wait up to 60 seconds for CLI to complete first
  • Acquisition: xSemaphoreTake(serialMutex, timeout)
  • Release: xSemaphoreGive(serialMutex) after output

NVS Mutex​

Settings writes use a separate NVS mutex (g_settingsMutex):

  • Timeout: 5000ms
  • Atomic Writes: Two-slot atomic NVS writes for safety
  • Corruption Detection: CRC32 validation on reads

  • Buffer Samples: 512-4096 samples

  • Threshold: 0-100 (arbitrary units)
  • Recording Times: 0-2147483647 ms

  • API Port: 1-65535
  • WiFi TX Power: 1-10 (relative levels)

Settings Storage​

Settings are stored in ESP32 NVS (Non-Volatile Storage) with:

  • Two-Slot Atomic Writes: Prevents corruption on power loss
  • CRC32 Validation: Detects corrupted settings
  • Active Slot Tracking: Knows which slot is valid
  • Backup Restoration: Falls back to backup on read failure
  • Auto-Save Debouncing: 1-second debounce before NVS write (auto-save)
  • Settings Lock: Prevents accidental changes from being saved to NVS
  • Explicit Save: SAVE command forces immediate write (respects lock)

Storage Format​

Per Slot: [CRC32:4 bytes][JSON:variable length]

  • CRC is stored little-endian
  • JSON is compact (abbreviated keys)
  • Total max: ~3500 bytes per slot
